# AGENTS.md

conduit is an opinionated integration of Apache Hamilton (DAG execution), xarray (+ dask), and `xarray-annotated` (contract validation: units, dims/coords/dtype, frequency), driven by a TOML spec that can describe a whole DAG — including dynamically generated nodes — in plain text. Its value is the *integration*: favour exposing Hamilton and xarray machinery over building opaque wrappers. It is alpha software with no external users, so **backwards compatibility is not a constraint** — make breaking changes (config schema, public APIs, behaviour) freely rather than adding compatibility shims.

- **Commands**: `just lint` (ruff format + check --fix; modifies files), `just lint-check` (read-only), `just test`, `just test-cov` (fails under 90% coverage), `just typecheck` (pyright), `just docs`. Pre-commit hooks run `uv-lock`, `pyright`, and `ruff` — not the test suite.
- **The flagship feature is the whole-DAG, before-compute contract check** (`contract_check.py`), which lifts `xarray-annotated`'s per-function contracts to a DAG-wide guarantee. Preserve and extend it; never bypass it.
- **A subpackage exists only when its contents are behind an install extra.** `conduit/cli/` needs the `cli` extra and `conduit/gridded/` needs `geo`; everything else is a top-level module in `conduit/`, however many there are. The Hamilton boundary that `dag/` used to mark is a test instead (`tests/test_layout.py`): `hamilton` may only be imported by `build`, `nodegen`, `caching`, `blocking`, `contract_check`, `wiring_check` and `graph`. Put a new module at the top level and add it to `docs/reference/modules/`, the nav in `zensical.toml`, and the map in `docs/reference/python-api.md`.
- **The library is the product; the CLI is an optional wrapper.** `run`/`dry_run` live in `pipeline.py`, `build_graph` in `graph.py`, and `conduit/cli/` only turns options into calls on them and renders the result. typer ships in the optional `cli` extra, so **no module outside `conduit.cli` may import it** (there is a test). Anything a command can do must be doable from Python — add behaviour to the library module and call it from the command, never the other way round.
- **Module docstrings are user-facing.** Every module listed under `docs/reference/modules/` renders its docstring into the published API reference, so a docstring says what the module does and how to use it — never why it is built that way. Keep out design rationale, justifications for where code lives, and claims about a module's own importance ("the single source of truth for…", "adding a format means adding one entry"). Nothing user-facing should explain what is absent, or lean on a "X, not Y" contrast to make its point. A constraint a maintainer could break by not knowing it goes in a plain comment at the code it constrains; the decision behind it is recorded in the maintainer's project notes, outside this repository.
- **`specs.py` is a deliberate leaf**: the only conduit module it may import is `errors.py`, which itself imports nothing at all, so no cycle is possible. The specs are what `io`, `checks`, `build` and `nodegen` all need to talk about, and while they lived in `config.py` — next to the TOML parser, which imports `checks` to validate check names — every one of those modules had to import `config` lazily to dodge a `config -> checks -> io -> config` cycle. Splitting the data model out removed the cycle rather than working around it, which is what keeps `config`/`io`/`checks` acyclic. Do not add any other conduit import to it.
- **Errors conduit raises on purpose come from `errors.py`** (`ConduitValueError`, `ConduitFileNotFoundError`, `ConduitPermissionError`; each keeps the stdlib type a caller would catch). The CLI prints a `ConduitError` as a bare message and exits 1; everything else keeps its traceback, because that is a bug and the frames are the point. Raise a bare `ValueError` only for a condition you did not anticipate.
- **Unknown TOML sections are a hard error**, not silently ignored. Any unrecognised section is treated as a user module and must carry `_import_path`.
- **Section labels are inert.** `daily`/`weekly`/`static` (or anything else) only name nodes via a suffix — no frequency or semantics is inferred from them. Frequency comes from declared `Freq` contracts; `conduit graph`'s clustering likewise derives from contracts, never from names.
- **`time` is never assumed as an axis name**: `io.time_dims` / `io.sole_time_dim` are the single time-axis detector. The core is likewise CRS/pixel-free; geospatial and parallel-Zarr code lives only in the optional `conduit.gridded` subpackage (lazy imports).
- **Keyword-only args (after `*`) from all config sections share one flat Hamilton namespace.** A name collision between two sections is a parse-time error naming both sections — choose parameter names accordingly.
- **Decorator order on node functions matters**: `declare_units` must be outermost (`declare_units(declare_freq(declare_schema(fn)))`), because it is the only one that may convert values rather than merely validate.
- **`nodegen.py` generates Hamilton modules from `[[node]]` TOML entries via `exec()`** (a node expression is arbitrary user code). Node names/inputs are validated as identifiers — and against `RESERVED_NODE_NAMES` — at parse time in `NodeSpec.from_config`; keep that validation intact if you touch this path.
- **`gridded.create_output_store` probes the DAG over a single pixel** to derive each output's non-`pixel` axes, so the store layout is by construction what subset runs write — including axes no input file has (e.g. a `[[resample]]`'s time axis). Do not "simplify" this to inspecting input files.
- **Tests** use session-scoped synthetic netCDF fixtures (`tests/conftest.py` ← `tests/synthetic_data.py`); the session pipeline (`tests/test_config.toml`) is deliberately model-free — a single `[[node]]` derived variable stands in for a model.
