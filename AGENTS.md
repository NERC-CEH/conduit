# AGENTS.md

conduit is an opinionated integration of Apache Hamilton (DAG execution), xarray (+ dask), and `xarray-annotated` (contract validation: units, dims/coords/dtype, frequency), driven by a TOML spec that can describe a whole DAG — including dynamically generated nodes — in plain text. Its value is the *integration*: favour exposing Hamilton and xarray machinery over building opaque wrappers. It is alpha software with no external users, so **backwards compatibility is not a constraint** — make breaking changes (config schema, public APIs, behaviour) freely rather than adding compatibility shims. `CONTRIBUTING.md` holds the design principles, the checklist for adding a recipe, and the docs structure.

- **Commands**: the justfile calls tools bare, so run `uv run just <task>` unless `.venv` is active. `just lint` (ruff format + check --fix; modifies files), `just lint-check` (read-only), `just test`, `just test-cov` (fails under 90% coverage), `just typecheck` (pyright), `just docs`. Pre-commit hooks run `uv-lock`, `pyright`, and `ruff` — not the test suite.
- **CI tests Python 3.12–3.14**, so write for 3.12. `just docs` executes every recipe notebook, so it is slow, and CI runs it on every PR. Graph tests skip when graphviz's `dot` binary is missing, so a local pass can hide a graph failure.
- **`[tool.uv] exclude-newer = "1 week"`**: a dependency release less than a week old will not resolve. `marimo-md-export` and `xarray-annotated` are exempt.
- **`xarray-annotated` is developed alongside conduit by the same maintainer.** When the contract machinery falls short, the fix may belong upstream; raise it rather than working around it here.
- **The flagship feature is the whole-DAG, before-compute contract check** (`contract_check.py`), which lifts `xarray-annotated`'s per-function contracts to a DAG-wide guarantee. Preserve and extend it; never bypass it. Its current limits are under "What contracts cannot catch" in `docs/concepts/contracts.md`.
- **A subpackage exists only when its contents are behind an install extra.** `conduit/cli/` needs the `cli` extra and `conduit/gridded/` needs `geo`; everything else is a top-level module in `conduit/`. Only the modules in `HAMILTON_IMPORTERS` (`tests/test_layout.py`) may import `hamilton`. A new module needs a page in `docs/reference/modules/`, an entry in the `zensical.toml` nav, and a row in the map in `docs/reference/python-api.md`; `tests/test_docs.py` checks all three.
- **The library is the product; the CLI is an optional wrapper.** `run`/`dry_run` live in `pipeline.py`, `build_graph` in `graph.py`, and `conduit/cli/` only turns options into calls on them and renders the result. No module outside `conduit.cli` may import typer (there is a test). Anything a command can do must be doable from Python — add behaviour to the library module and call it from the command, never the other way round.
- **Module docstrings are user-facing**: they render into the published API reference. A docstring says what the module does and how to use it. Keep out design rationale, justifications for where code lives, claims about a module's own importance, explanations of what is absent, and "X, not Y" contrasts. A constraint a maintainer could break by not knowing it goes in a plain comment at the code it constrains; the decision behind it lives in the maintainer's project notes, outside this repository.
- **`specs.py` may import only `errors.py`, and `errors.py` imports nothing** (`tests/test_layout.py` enforces both). Dependencies point into `specs`, never out: put shared data there (e.g. `RESERVED_NODE_NAMES`) and import it from the consumer.
- **Errors conduit raises on purpose come from `errors.py`** (`ConduitValueError`, `ConduitFileNotFoundError`, `ConduitPermissionError`; each keeps the stdlib type a caller would catch). Use them for any condition a user can cause and fix; the CLI shows them without a traceback. A bare `ValueError` means a bug.
- **Unknown TOML sections are a hard error**, not silently ignored. Any unrecognised section is treated as a user module and must carry `_import_path`.
- **Section labels are inert.** `daily`/`weekly`/`static` (or anything else) only name nodes via a suffix — no frequency or semantics is inferred from them. Frequency comes from declared `Freq` contracts; `conduit graph`'s clustering likewise derives from contracts, never from names.
- **`time` is never assumed as an axis name**: `io.time_dims` / `io.sole_time_dim` are the single time-axis detector. The one exception is single-point CSV/Parquet input (`formats._timeseries_from_frame`), where a table has no other way to name its index. The core is likewise CRS/pixel-free; geospatial and parallel-Zarr code lives only in the optional `conduit.gridded` subpackage (lazy imports).
- **Keyword-only args (after `*`) from all config sections share one flat Hamilton namespace.** A name collision between two sections is a parse-time error naming both sections — choose parameter names accordingly.
- **Decorator order on node functions matters**, in user modules and recipes as well as `nodegen`: `declare_units` must be outermost (`declare_units(declare_freq(declare_schema(fn)))`), because it is the only one that may convert values rather than merely validate.
- **`nodegen.py` generates Hamilton modules from `[[node]]` TOML entries via `exec()`** (a node expression is arbitrary user code). Node names and inputs are validated as identifiers, and against `specs.RESERVED_NODE_NAMES`, at parse time in `NodeSpec.from_config`; keep that validation intact if you touch this path.
- **Tests** use session-scoped synthetic netCDF fixtures (`tests/conftest.py` ← `tests/synthetic_data.py`); the session pipeline (`tests/test_config.toml`) is deliberately model-free — a single `[[node]]` derived variable stands in for a model.
